In Phase 2, a small database connectivity fault was tested on Azure SQL Server

Restore path tested first: set publicNetworkAccess=Enabled and confirmed.
Fault injected: set publicNetworkAccess=Disabled (simulated access outage).
Rollback validated: set publicNetworkAccess=Enabled again and confirmed.



training [ ~ ]$ RG="rg-aiinfra-Nandhini"
SQL="sql-7g0iy"
MYIP="$(curl -s https://api.ipify.org)"
RULE="allow-cloudshell-ip"

# 1) Prove restore path first (safety gate)
az sql server update -g "$RG" -n "$SQL" --set publicNetworkAccess=Enabled -o none
az sql server firewall-rule create -g "$RG" -s "$SQL" -n "$RULE" --start-ip-address "$MYIP" --end-ip-address "$MYIP" -o none
az sql server show -g "$RG" -n "$SQL" --query "{server:name,publicNetworkAccess:publicNetworkAccess}" -o table

# 2) Inject small fault
az sql server update -g "$RG" -n "$SQL" --set publicNetworkAccess=Disabled -o none
az sql server show -g "$RG" -n "$SQL" --query "{server:name,publicNetworkAccess:publicNetworkAccess}" -o table

# 3) Rollback
az sql server update -g "$RG" -n "$SQL" --set publicNetworkAccess=Enabled -o none
az sql server show -g "$RG" -n "$SQL" --query "{server:name,publicNetworkAccess:publicNetworkAccess}" -o table
